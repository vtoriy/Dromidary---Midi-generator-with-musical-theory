# Аппаратная часть

## Компоненты

| Компонент | Модель | Интерфейс |
|---|---|---|
| MCU | Raspberry Pi Pico (RP2040) | — |
| Дисплей | SH1106 OLED, 132×64, монохромный | I2C (800kHz) |
| Кнопки (24 шт: 16 нот + 8 функций/зарезервировано) | — | 2× 74HC165 (каскад, SPI-like) |
| Джойстик | KY-023 | 2× аналоговый вход (X/Y) + 1 цифровая кнопка |
| MIDI (текущее) | USB MIDI | `usb_midi` + `adafruit_midi` |
| MIDI (план) | UART DIN 5-pin | 1× UART TX (OUT), 1× UART RX + оптрон (IN) |

## Текущая распиновка (из рабочего прототипа)

```
Дисплей (I2C):
  GP0  — I2C SDA
  GP1  — I2C SCL
  (адрес дисплея: 0x3C)

Сдвиговые регистры 74HC165 (каскад из двух чипов, итого 24 бита):
  GP2  — LATCH (общий для обоих чипов)
  GP3  — CLK   (общий)
  GP4  — DATA  (serial out последнего чипа в цепочке)

Джойстик KY-023:
  GP26 — X (ADC0)
  GP27 — Y (ADC1)
  GP15 — кнопка джойстика (INPUT, PULL.UP, активный уровень LOW)
```

Свободные пины на момент написания — доступны для UART MIDI (TX/RX) и, при
добавлении MIDI IN, для оптрона (6N138 / PC900 или аналог). Точный выбор GP-пинов
под UART зафиксировать отдельно перед разводкой (любой UART RP2040 подходит,
конфликтов с занятыми пинами по текущей схеме нет).

## Битовая карта 74HC165 (24 бита, читаются одним sequential shift-in)

Чтение идёт одним 24-битным словом (`read_all_chips()` в прототипе), затем
разбирается на 3 байта:

```
raw = read_all_chips()          # 24 бита
chip3 = (raw >> 16) & 0xFF       # кнопки управления (Play/Rec/...)
chip2 = (raw >> 8)  & 0xFF       # ноты 9–16
chip1 = raw & 0xFF                # ноты 1–8
```

Активный уровень — **низкий** (`not (chip >> i) & 1` = нажата).

### Битовая карта chip3 (функциональные кнопки, подтверждено 02.08.2026 по логу FUNC)

| Бит chip3 | Кнопка |
|---|---|
| bit0 | Play |
| bit1 | **Rest** |
| bit2 | **Rec** |
| bit3 | **Shift** |
| bit4 | не используется (всегда читается 0) |
| bit5 | не используется (всегда читается 0) |
| bit6 | **OctUp** («+») |
| bit7 | **OctDown** («−») |

История: изначально (до 02.08.2026) предполагалось OctDown=bit2, OctUp=bit3,
Rest=bit6, Shift=bit7 по логу `FUNC`. Тестовая прошивка (подсветка кнопок «+»/«−»)
показала, что октава сидит на битах 6–7. Лог `FUNC` 02.08.2026 (1 = нажато,
сверка с физическими нажатиями) зафиксировал итог: Play=bit0, Rest=bit1, Rec=bit2,
Shift=bit3, **OctUp=bit6 («+»), OctDown=bit7 («−»)**.

Биты 4–5 физически ни к чему не подключены и **плавают**: в `code.py` они
маскируются (`chip3 &= 0xCF`) сразу после чтения, чтобы их дребезг не вызывал
флуд `FUNC`-лога и ложных срабатываний. При разводке платы их желательно
припаять к GND (или через резистор к +3.3V).

### Известная проблема: перепутанные провода на втором 74HC165 (D4–D7)

На плате диапазон D4–D7 второго регистра разведён неверно: физически кнопка №13
подключена к линии D7 вместо предназначенной ей D4 (соответственно сдвинуты и
соседние линии в этом квадранте). В коде это никак не компенсируется —
`chip2` читается "как есть", напрямую индексируясь битом `i`.

**Решение (зафиксировано 30.07.2026):** оставить как есть. Текущее подключение
работает, физическое расположение кнопок настроено под конкретную плату.
Программный remap не вносить. Если в будущем потребуется исправление —
перепаять на плате (вариант 1 ниже).

**Варианты решения (для справки):**
1. **Правильное** — перепаять линии на плате, тогда программный маппинг не нужен.
2. **Программное** — ввести таблицу перемаппинга бит для `chip2` (не применяется,
   оставлено для справки):
   ```python
   # placeholder — требует уточнения фактической разводки на плате
   CHIP2_BIT_REMAP = [0, 1, 2, 3, 7, 6, 5, 4]
   ```

**Важно:** не пытаться "исправить" код программным remapом — это замаскирует
аппаратную проблему и запутает отладку. Если кнопки читаются не так, как ожидается
— проверять соответствие физической разводки в первую очередь.

## MIDI: текущее и план

### Сейчас — USB MIDI
Библиотека `adafruit_midi` поверх `usb_midi.ports` уже подключена и работает.
Использовать `adafruit_midi.MIDI(midi_out=usb_midi.ports[1], midi_in=usb_midi.ports[0])`.

### План — аппаратный UART MIDI DIN
- **MIDI OUT**: 1 UART TX (RP2040 UART работает на 31250 бод для MIDI), выход через
  резисторы (типовая схема: 220Ω на TX и на +5V к пину 4 DIN-разъёма, пин 5 — TX
  через резистор, пин 2 — экран/земля).
- **MIDI IN**: обязательна гальваническая развязка через оптрон (6N138 или PC900V2),
  не подключать DIN IN напрямую к UART RX — риск земляных петель и повреждения пина.
  Стандартная схема на 6N138 общедоступна в даташитах MIDI-спецификации.
- Устройство сможет держать одновременно USB MIDI и UART MIDI как независимые порты
  (полезно для сценария "устройство между компьютером по USB и хардварным синтом по
  DIN").

### MIDI Clock (будущее)
Синхронизация BPM с внешним оборудованием потребует:
- приём `Clock` (0xF8), `Start` (0xFA), `Continue` (0xFB), `Stop` (0xFC) сообщений
  на MIDI IN, если устройство работает как slave;
- либо отправку тех же сообщений на MIDI OUT, если устройство — master.
Сейчас не реализуется — BPM только внутренний генератор (см. `07-roadmap-open-questions.md`).

## Дисплей и производительность

I2C на 800kHz — прогон полного кадра SH1106 132×64 занимает заметное время
относительно шагового таймера секвенсора. Рекомендации:
- обновлять дисплей **не каждый тик**, а по dirty-flag/изменению состояния
  (частично уже реализовано в прототипе — сравнение `last_chipN`);
- не запускать полное перерисовывание экрана в момент шага секвенсора — либо
  выносить обновление дисплея в конец цикла после отправки MIDI-события, либо
  ограничивать частоту обновления (например не чаще 20–30 Гц для анимаций).

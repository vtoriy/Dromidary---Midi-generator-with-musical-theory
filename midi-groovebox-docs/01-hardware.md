# Аппаратная часть

## Компоненты

| Компонент | Модель | Интерфейс |
|---|---|---|
| MCU | Raspberry Pi Pico (RP2040) | — |
| Дисплей | SH1106 OLED, 132×64, монохромный | I2C0 (SDA=GP0, SCL=GP1, addr 0x3C) |
| Кнопки (22 шт: 16 нот + 6 функциональных) | — | каскад 74HC165 (24 бита ввода) |
| Джойстик | KY-023 | 2× аналоговый вход (X/Y) + 1 цифровая кнопка |
| LED | встроенный на GP25 | — |
| MIDI (текущее) | USB MIDI | TinyUSB device class |
| MIDI (план) | UART DIN 5-pin | 1× UART TX (OUT), 1× UART RX + оптрон (IN) |

## Распиновка (фактическая, из `src/platform/board_pins.hpp`)

```
Дисплей (I2C0):
  GP0  — I2C SDA
  GP1  — I2C SCL
  (адрес дисплея: 0x3C)

Сдвиговый каскад 74HC165 (24 бита):
  GP2  — LATCH (общий для всех чипов)
  GP3  — CLK   (общий)
  GP4  — DATA  (serial out последнего чипа в цепочке)

Джойстик KY-023:
  GP26 — X (ADC0)
  GP27 — Y (ADC1)
  GP15 — кнопка джойстика (INPUT, PULL.UP, активный уровень LOW)

LED:
  GP25 — встроенный светодиод (индикация активности ввода)
```

Свободные пины на момент написания — доступны для UART MIDI (TX/RX) и, при
добавлении MIDI IN, для оптрона (6N138 / PC900 или аналог). Точный выбор GP-пинов
под UART зафиксировать отдельно перед разводкой (любой UART RP2040 подходит,
конфликтов с занятыми пинами по текущей схеме нет).

## Чтение каскада 74HC165 (24 бита)

Чтение — одним 24-битным словом `Shift165::read_all()`. Для подавления дребезга
линия пробуется дважды (двойной опрос) — возвращается результат, когда два
последовательных чтения совпадают. Разбор по байтам:

```
raw = read_all()            # 24 бита
chip3 = (raw >> 16) & 0xFF  # функциональные кнопки (Play/Rec/...)
chip2 = (raw >> 8)  & 0xFF  # ноты 9–16
chip1 = raw & 0xFF          # ноты 1–8
```

Активный уровень — **низкий** (`((raw >> bit) & 1) == 0` = нажата). В коде
используются «сырые» индексы битов: нотные клавиши — raw bits 0..15,
функциональные — raw bits 16..23 (chip3 bit i = raw bit 16+i).

Нотная раскладка (см. `05-input-mapping.md`): кнопки 1–12 = C..B текущей октавы,
кнопки 13–16 = C, C#, D, D# на октаву выше.

### Битовая карта chip3 (функциональные кнопки, подтверждено на контактах 74HC165)

| Бит chip3 | Raw bit | Кнопка |
|---|---|---|
| bit0 | 16 | **Play** |
| bit1 | 17 | **Rest** |
| bit2 | 18 | **Rec** (Record) |
| bit3 | 19 | **Shift** |
| bit4 | 20 | не подключено (плавает, маскируется) |
| bit5 | 21 | не подключено (плавает, маскируется) |
| bit6 | 22 | **OctUp** («+», D6) |
| bit7 | 23 | **OctDown** («−», D7) |

История: промежуточная правка (OctUp=bit5/OctDown=bit6) была ошибочной — давала
«+» понижение октавы и отсутствие LED на «−». По фактическим контактам 74HC165
подтверждено окончательно: **OctUp=bit6 (D6, «+»), OctDown=bit7 (D7, «−»)**.

Биты 4 и 5 физически ни к чему не подключены и **плавают**: в прошивке они
маскируются (`kUnusedMask = 0x00300000`, raw bits 20,21) при чтении, чтобы их
дребезг не вызывал флуд лога и ложных срабатываний (LED). При разводке платы их
желательно припаять к GND (или через резистор к +3.3V).

### Диагностика распиновки — экран Test

В Full-меню **System → Test** открывается экран диагностики ввода: показывает
текущий образ нотных клавиш (`note_bits`, бит i = клавиша i нажата) и
функциональных кнопок (`func_bits`, подтверждённый образ chip3). На этом экране
кнопки **не управляют** транспортом/октавой — только отображаются, чтобы
проверяющий видел чистые сигналы. Выход — **Shift + клик джойстика**. В test mode
CC-дубли функц. кнопок не отправляются (канал должен быть тихим для тестера).

### Известная проблема: перепутанные провода на втором 74HC165 (D4–D7)

На плате диапазон D4–D7 второго регистра разведён неверно: физически кнопка №13
подключена к линии D7 вместо предназначенной ей D4 (соответственно сдвинуты и
соседние линии в этом квадранте). В коде это никак не компенсируется — `chip2`
читается «как есть».

**Решение (зафиксировано 30.07.2026):** оставить как есть. Текущее подключение
работает, физическое расположение кнопок настроено под конкретную плату.
Программный remap не вносить. Если в будущем потребуется исправление —
перепаять на плате.

**Важно:** не пытаться «исправить» код программным remapом — это замаскирует
аппаратную проблему и запутает отладку. Если кнопки читаются не так, как ожидается
— проверять соответствие физической разводки в первую очередь.

## MIDI: текущее и план

### Сейчас — USB MIDI
TinyUSB device class (`tusb_config.h`, `usb_descriptors.c`). Отправка событий —
`UsbMidi`:

- Note On: packet `{0x09, 0x90, note, velocity}` (velocity фикс. 100);
- Note Off: packet `{0x08, 0x80, note, 0x00}`;
- Control Change: packet `{0x0B, 0xB0|chan, control, value}`.

**CC-дубли функциональных кнопок** (для назначения в DAW, канал 16, нажатие=127,
отпускание=0): Play→CC20, Rest→CC21, Rec→CC22, Shift→CC23, OctUp→CC24, OctDn→CC25.
Отправляются только вне test mode.

### План — аппаратный UART MIDI DIN
- **MIDI OUT**: 1 UART TX (RP2040 UART работает на 31250 бод для MIDI), выход через
  резисторы (типовая схема: 220Ω на TX и на +5V к пину 4 DIN-разъёма, пин 5 — TX
  через резистор, пин 2 — экран/земля).
- **MIDI IN**: обязательна гальваническая развязка через оптрон (6N138 или PC900V2),
  не подключать DIN IN напрямую к UART RX — риск земляных петель и повреждения пина.
- Устройство сможет держать одновременно USB MIDI и UART MIDI как независимые порты.

### MIDI Clock (будущее)
Синхронизация BPM с внешним оборудованием. Сейчас не реализуется — BPM только
внутренний (см. `07-roadmap-open-questions.md`).

## Производительность

Главный цикл `AppLoop::run()`:

- `tud_task()` + чтение 24-битного каскада — каждый проход (~1 мс `sleep_ms(1)`);
- обработка функц. кнопок и нот с дебаунсом;
- джойстик (опрос ADC X/Y + кнопка), навигация меню с авто-повтором (190 мс и
  ускоряющийся при долгом удержании);
- `mode_.tick()` — планировщик арпеджио / RandomNote;
- инкрементальный рендер в буфер (только при `ui_dirty_`), вывод кадра — не чаще
  `kFlushMs = 40` мс; Animation обновляется раз в ~83 мс (12 FPS);
- клик-настройки сохраняются во flash через 500 мс после последнего изменения.

Рендер не блокирует MIDI-путь: обновление дисплея — отдельная фаза с ограничением
частоты, чтобы не сдвигать ритм арпеджио.

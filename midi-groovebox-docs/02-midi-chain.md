# Конвейер обработки ноты (Note Processing Chain)

Центральная логика устройства. Порядок зафиксирован и не должен меняться без
пересмотра всей цепочки — каждый последующий этап полагается на то, что предыдущий
уже гарантировал тональность/структуру.

Реализация в C++: `ModeEngine` (live-игра, арпеджио, RandomNote) вызывает
`build_note_set()` из `src/engine/midi_chain.cpp` и `chord_builder.cpp`. Порядок
этапов внутри конвейера:

```
[Источник ноты]
   note-key (или случайная нота RandomNote)
        │
        ▼
[0. TRANSPOSE]                 — полутоны + октавы (всегда, до Key Filter)
        │
        ▼
[1. KEY FILTER]               — если включён (16 ладов, snap up/down/mute)
        │
        ▼
[2. CHORD BUILDER]            — если включён (26 типов аккордов)
        │
        ▼
[3. "secondary filter"]       — если Key Filter включён: фильтрация всей
        │                        структуры аккорда целиком
        ▼
[4. ARPEGGIATOR / live]      — перебор полученного набора нот (если вкл.)
        │
        ▼
[5. TIMING]                 — swing / humanize / quantize / legato: сдвиг
        │                     момента следующего шага арпеджио
        │
        ▼
[6. GATE/ADSR + VOICING]   — attack до Note On; release продлевает Note Off;
        │                     Strum/Roll раскидывает ноты аккорда в очередь
        ▼
   USB MIDI Note On/Off → OUT
```

> **Статус:** с текущего релиза timing-эффекты, gate/ADSR и voicing Strum/Roll
> подключены к live-выводу через планировщик задержанных событий в `ModeEngine`
> (очередь `pending_`, flush в `tick()`). Эти настройки применяются к арпеджио
> сразу же (не входят в «отпечаток» арпа, см. ниже) — меню не перезапускает
> арпеджио при их изменении.

## Этап 0 — Transpose (транспонирование)

Применяется к сырой ноте **до** Key Filter, чтобы транспонированная нота тоже
корректно снималась в тональность:

```
note = raw_note + transpose.semitones + transpose.octaves * 12
```

Влияет и на живой ввод, и на арпеджио (входит в «отпечаток» арп-конфигурации,
см. ниже). Значения: полутоны −12..+12, октавы −4..+4.

### Октава нотных клавиш

Базовая октава нотных клавиш (`runtime.base_octave`, по умолчанию 2) не входит в
`transpose` конвейера — она запекается в сырую ноту в `AppLoop::button_to_note()`
до вызова конвейера. Раскладка (конвенция C3=60, `kMidiOctaveOffset = 2`):

```
note = (base_octave + 2 + 1_if_index>=12) * 12 + (index % 12),  index = 0..15
```

Кнопки 1–12 (index 0..11) = C..B текущей октавы; кнопки 13–16 (index 12..15) =
C, C#, D, D# на октаву выше. Меняется через OctUp/OctDn или меню
Full → Transpose → Base Octave (1–8). Чисто программно, без MIDI-сигналов.

## Этап 1 — Key Filter (фильтр по тональности)

Вход: нота уже с учётом транспонирования и октавы.

- `enabled`, `root_note` (C..B), `scale` (16 ладов: Off, Major, Minor, Dorian,
  Phrygian, Lydian, Mixolydian, Locrian, HarmonicMinor, MelodicMinor,
  PentatonicMajor, PentatonicMinor, Blues, WholeTone, Diminished, Chromatic),
  `mode` = SnapUp / SnapDown / Mute.
- Если нота не в ладу: `SnapUp` — поднять до ближайшей в ладу, `SnapDown` —
  опустить, `Mute` — проглотить (`muted`, нота не звучит).
- Если нет подходящей ноты в диапазоне (snap за границей MIDI) — нота глушится.

Интервальные паттерны — `kScaleIntervals` в `key_filter.cpp`.

## Этап 2 — Chord Builder (аккорды)

Строится из ноты, уже прошедшей Key Filter. `ChordCfg`: `enabled`, `type` (26 типов
+ Off), `voicing` (Block/Strum/Roll), `strum_delay_ms`. Типичные наборы интервалов:

- трязувия: Major (0,4,7), Minor (0,3,7), Diminished (0,3,6), Augmented (0,4,8);
- септаккорды: Maj7, Min7, Dom7, Min7b5, Dim7;
- протяжённые: 9, 11, 13, Maj9;
- альтерации: 7#5, 7#9, 7b9, 7#11;
- sus: Sus2, Sus4, 7sus4, Sus2/7;
- quartal/quintal (0,5,10 / 0,7,14), Cluster (0,1,2,3), Power (0,7).

`voicing`/`strum_delay_ms` применяются в live-выводе: **Block** — все ноты набора
уходят сразу; **Strum** — ноты стартуют с задержкой `strum_delay_ms` друг за другом
и удерживаются до отпускания клавиши; **Roll** — ноты стартуют так же поочерёдно,
но каждая, кроме последней, "отпускается" через один `strum_delay_ms` (короткое
переборное звучание), последняя — держится до отпускания. Для аккорда из одной
ноты разница между способами отсутствует.

## Этап 3 — Secondary filter (вторичная фильтрация структуры)

Если Key Filter включён — вся получившаяся структура аккорда заново прогоняется
через тот же фильтр (SnapUp/Down/Mute), но **к структуре целиком**: каждая нота
дорожки не сводится к случайному интервалу — сохраняется роль ступени, а ноты,
не имеющие «мягкого» попадания в лад, отбрасываются. Если фильтр выключен —
аккорд остаётся хроматическим.

## Этап 4 — Arpeggiator (live)

Работает в режимах MIDI-клавиатура (и технически доступен в midi_filter, но этот
режим в alpha не включён в меню). Вход — объединённый набор нот:

- в live-игре все зажатые клавиши объединяются в один аккорд
  (`build_note_set()` на каждую → дедупликация → сортировка по высоте);
- параметры арпеджио (именование Rate / Distance / Steps / Cycle):
  - **Rate** — скорость шагов: `rate_mode == Note` → доли такта (деления
    1/64..1/1 с учётом BPM, включая триоли 1/48, 1/24, 1/12, 1/6, 1/3);
    `rate_mode == Ms` (в UI «Free») → 10..2000 мс, шаг 10;
  - **Distance** — `distance_semitones` (0..48, по умолчанию 12): интервал
    транспонирования каждого следующего прохода паттерна;
  - **Steps** — `steps` (0..16): сколько дополнительных транспозиций делает
    паттерн. Сначала звучит исходная высота, каждый следующий проход смещается
    на Distance; всего позиций `steps+1`. Пример (мануал): Distance +12, Steps 2
    → паттерн от C3 звучит как C3 → C4 → C5. Steps 0 = только исходная высота;
  - **Cycle** — `cycle` (1..32): через сколько шагов повторяется цикл
    арпеджио (бывш. `num_steps`);
- расширение набора: каждая нота базы дублируется `steps+1` раз с шагом
  `distance_semitones` (колонки клавиатуры), затем набор фильтруется по
  включённой тональности (Key Filter) и сортируется;
- одиночная нота при `steps > 0 && distance > 0` арпеджируется по той же
  гриде позиций; одиночная нота без расширения циклится без повтора.

Live-планировщик (`ModeEngine::tick()`): сетка якорится на момент нажатия, при
опоздании не сдвигается. При `latch` ON залипание ноты держится после отпускания;
при `latch` + арп — нажатие новой клавиши заменяет предыдущую (моно-замена).
Уникальные (aside retrigger): если следующая нота цикла совпадает со звучащей —
не пердозвучит (без «перкуссивного» перестука).

### Fingerprint арпеджио

`arp_fingerprint()` — хэш всех параметров, влияющих на последовательность арпа
(вкл./latch/rate/distance/steps/cycle/style, аккорд, транспонирование, BPM из
`TimingCfg`, режим).
Меню навигации само по себе НЕ перезапускает арпеджио — пересборка только когда
хэш изменился (`on_arp_config_changed()`).

Timing-параметры (`TimingCfg`) намеренно НЕ входят в «отпечаток»: их изменение
влияет только на моменты шагов, не на последовательность нот, поэтому арпеджио
подхватывает их с ближайшего шага без перезапуска. Исключение — `TimingCfg.bpm`:
темп входит в fingerprint и при изменении BPM последовательность (точнее способ
её расчёта) пересобирается.

> **BPM перенесён из `Pattern` в `TimingCfg`**: редактируется в секции Timing
> FULL-меню и в DETAIL-подменю (бывш. в Pattern). В QUICK добавлена строка
> **Time**: клетки Swing (радиальные зоны), Quant (сетка квантизации) и PRM →
> DETAIL-список BPM/Swing/Human/Quantize/Legato.

## Этап 5 — Timing (swing / humanize / quantize / legato)

Применяется к планировщику шагов арпеджио (`ModeEngine::next_arp_onset()`):

- **swing** (`swing_pct` 0..100): шаг, следующий за первым в каждой паре
  («off-beat»), задерживается на долю длительности шага: `interval * swing/100`.
  Арпеджио автоматически становится «качающимся» при нечётных долях.
- **humanize** (`humanize_ms` 0..50): момент каждого шага сдвигается вперёд на
  детерминированный псевдослучайный сдвиг 0..N мс (тот же `SimpleRng`, что у
  Random-стилей).
- **quantize** (`quantize_grid`): после swing/humanize момент следующего шага
  округляется вверх до ближайшей границы сетки (1/32..1/4, см.
  `kQuantizeGrids` в `03-data-structures.md`). При `Off` — сетки нет.
- **legato** (`bool`): при смене ноты арпа предыдущая не глушится сразу, а
  «перехлёстывается» — получает Note Off через один интервал шага, создавая
  непрерывное звучание (перекрытие нот) вместо разрыва.

Для непрерывного RandomNote тайминг-сдвиги не применяются (неты идут фиксированно
через `arp_interval_ms`).

## Этап 6 — Gate/ADSR (attack / release)

Применяется через очередь задержанных Note On/Off (`ModeEngine::pending_`):

- **attack_ms** — Note On каждой ноты задерживается на указанное время
  (арп, аккорд/Block/Strum/Roll и RandomNote).
- **release_ms** — Note Off каждой ноты продлевается: при отпускании клавиши,
  смене ноты арпа или остановке генерируемого звука.
- Фазы `decay_ms` / `sustain_pct` не имеют отображения в MIDI (нет velocity-выхода)
  и остаются зарезервированными; ADSR здесь — модель тайминга (атака/раздержка).
- При `gate.enabled == false` задержки не применяются (атака/релиз = 0).

Отмена несозданных Note On: при отпускании клавиши до срабатывания её
задержанных Note On (например `attack > 0` или strum ещё не доиграл) — эти
Note On отменяются, звук не выдаётся; отпускание исполняется через релиз.

## RandomNote (непрерывная случайная нота)

Режим включается ячейкой **Mode** (KB ↔ RND) или кнопкой Play. Логика
(`ModeEngine::random_loop_*`):

- якорь — октава/нота нажатой клавиши (или C текущей октавы при кнопке Play);
- случайная нота выбирается в полосе ±2 октавы вокруг якоря (центр — октава ниже),
  фильтруется в текущую тональность (до 16 попыток);
- темп следования нот — текущая частота арпеджио (`arp_interval_ms()`);
- при совпадении со звучащей нотой — нота не забывается, нота эта не отдёргивается
  (продолжает звенеть до другой ноты);
- повторное нажатие той же клавиши, что дала текущую ноту, выключает генерацию
  (toggle) и гасит ноту; повторное нажатие любой другой клавиши — меняет якорь;
- остановка — снова Play или выход из режима (все ноты гасятся).

> Метка ноты на дисплее (статус-бар) обновляется при каждом шаге арпеджио и
> каждой новой случайной ноте даже без нажатий: `ModeEngine::take_ui_dirty()`
> выставляет флаг repaint, который опрашивает главный цикл после `tick()`.

## Итоговый порядок применения (сводка)

1. Транспонирование (полутоны/октавы) — до Key Filter
2. Key Filter (16 ладов, snap up/down/mute)
3. Chord Builder (26 типов аккордов; voicing Block/Strum/Roll — на выходе)
4. Secondary key filter (структурная фильтрация аккорда, если Key Filter вкл.)
5. Arpeggiator (объединение зажатых клавиш → колонки keys×range → фильтр
   тональности → style-цикл, включая Chord Trigger)
6. Timing (swing/humanize/quantize — сдвиг шага арпа; legato — перехлёст нот)
7. Gate/ADSR (attack до Note On, release после Note Off)
8. Voicing: удержание/раскидка аккорда во времени (Block/Strum/Roll)
9. USB MIDI Note On/Off → OUT
   (+ CC-дубли функц. кнопок, см. `01-hardware.md`)

Примечания:
- Тайминговые этапы (6–7) применяются только при включённых соответствующих
  настройках; во всех дефолтных паттернах вывод идентичен прежнему «Block + мс».
- Набор нот из одной зажатой клавиши — это ≥1 нота; для арпеджио с 1 нотой нужен
  `keys > 1` с `range_semitones > 0` или включённый аккорд, иначе все стили
  звучат одинаково.

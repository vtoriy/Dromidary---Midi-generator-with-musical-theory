# Конвейер обработки ноты (Note Processing Chain)

Это центральная логика устройства. Порядок зафиксирован и не должен меняться без
пересмотра всей цепочки — каждый последующий этап полагается на то, что предыдущий
уже гарантировал тональность/структуру.

```
[Источник ноты]
   note-key │ random-note │ random-pattern-step │ midi-in
        │
        ▼
[1. KEY FILTER]                — если включён
        │
        ▼
[2. CHORD BUILDER]             — если включён
        │
        ▼
[3. ARPEGGIATOR]                — если включён
        │
        ▼
[4. TIMING-ЭФФЕКТЫ] (не трогают pitch)
   swing/groove → humanize → triole/quantize → legato
        │
        ▼
[5. GATE/ADSR] (эффект поверх готовой длины ноты)
        │
        ▼
   MIDI Note On/Off → USB MIDI OUT (позже + UART MIDI OUT)
```

## Этап 1 — Key Filter (фильтр по тональности)

Вход: сырая нота (raw MIDI note number) из любого источника.
Настройки: ключ (нота), тональность (лад), режим обработки ошибочной ноты:
- `SNAP_UP` — поднять до ближайшей ноты, входящей в тональность;
- `SNAP_DOWN` — опустить до ближайшей;
- `MUTE` — не воспроизводить (нота "проглатывается").

Если фильтр выключен — нота проходит без изменений.

**Важно**: применяется к нотам из ЛЮБОГО источника — нотные клавиши, случайная
нота, случайный паттерн, MIDI-input. Функция строится один раз и переиспользуется
всеми источниками.

**Транспонирование** (`pattern.transpose`, полутоны + октавы) применяется к сырой
ноте **до** этапа 1 (Key Filter), чтобы транспонированная нота тоже корректно
снималась в тональность. Это влияет и на живой ввод, и на записанные ноты при
воспроизведении (см. `05-input-mapping.md`, "Октавы и транспонирование").
Базовая октава нотных клавиш (OctUp/OctDn, `runtime.base_octave`) не добавляется
внутри `process_note` — она запекается `code.py` в сырую ноту нотных клавиш
(`note = base_octave*12 + (i % 12)`) перед вызовом конвейера, поэтому на вход
этапа 1 нота уже приходит с учётом октавы. Меняется только через
OctUp/OctDn или меню MAIN → Octave (чисто программно, без MIDI-сигналов).

## Этап 2 — Chord Builder (аккорды)

Работает только если Key Filter в принципе доступен для активации (по таблице
режимов — см. `06-mode-matrix.md`, режимы MIDI-клавиатура, случайная нота,
MIDI-фильтр поддерживают аккорды; режимы "паттерн" и "случайный паттерн" — нет).

Вход: `root_note` — уже прошедшая через Key Filter нота.

1. Строится интервальная структура аккорда согласно выбранному типу (см.
   `05-input-mapping.md`, радиальный селектор джойстика — типы аккордов).
2. **Если Key Filter включён** — вся получившаяся структура (все ноты аккорда)
   повторно прогоняется через тот же режим обработки (SNAP_UP/DOWN/MUTE), но
   применяется **к структуре целиком**, а не к каждой ноте изолированно —
   т.е. сохраняется роль каждой ступени (терция/квинта/септима), меняется только
   конкретная высота, чтобы не разваливать форму аккорда на случайные интервалы.
3. **Если Key Filter выключен** — аккорд остаётся полностью хроматическим, без
   всякой коррекции.

Настройка манеры игры аккорда (после того как набор нот определён):
- **Block** — все ноты одновременно (Note On синхронно);
- **Strum/смещение** — ноты друг за другом с небольшой задержкой (по образцу
  гитарного боя), задержка — параметр в мс или долях шага;
- **Arpeggiated/перебор** — поочерёдная игра нот аккорда как отдельная манера
  игры (не путать с полноценным арпеджиатором из этапа 3 — это более простой
  "разбор аккорда", если пользователю не нужен полный арпеджиатор с rate/style).

## Этап 3 — Arpeggiator

Вход: набор нот с этапа 2 (одна нота, если аккорд не активен — тогда арпеджио
играет по `range_semitones`, гуляя за пределы набора; реализовано).

В live-режиме арпеджио **полифонично по набору клавиш** (02.08.2026): все
зажатые клавиши объединяются (`ModeEngine._arp_notes: chip_idx -> raw_note`)
в общий аккорд через Key Filter → Chord Builder, и `_arp_playing` играет
единым голосом по отсортированному объединению. Нажатие/отпускание клавиши
пересобирает аккорд и перезапускает цикл арпеджио (`_restart_arp`). Планировщик
live — `tick()` по `time.monotonic()` с интервалом из `arp_cfg.rate` и BPM;
вызывается в главном цикле `code.py`. Без арпеджио одновременные клавиши играют
полифонично (по `_held_notes[chip_idx]` на каждую).

**Latch (02.08.2026):** при latch ON + арпеджио полифония не действует —
нажатие новой клавиши **заменяет** ранее защёлкнутую (`_latched`/`_arp_notes`
чистятся под новую клавишу, арп перезапускается на ней). Повторное нажатие той же
защёлкнутой клавиши — отпускает.

**Автопроверка конфигурации (`_check_config` в `tick()`):** выключение арпеджио в
меню немедленно гасит звучащий арп (`_stop_arp()` + очистка `_arp_notes`);
выключение latch снимает защёлки — арп-ноты гасятся, залипшие обычные ноты
отпускаются (`_release_chip`), при пустом наборе арп останавливается.

Так как входящий набор нот уже отфильтрован по тональности, арпеджиатор **не
может** самостоятельно вывести ноты за пределы лада — дополнительная фильтрация
здесь не требуется (кроме намеренного `range_semitones`).

Параметры:
- вкл/выкл (радиальный селектор, см. `05-input-mapping.md`);
- rate — единый параметр **Rate** (объединяет бывшие RateDiv и RateMs, 02.08.2026)
  с переключателем режима **RateMode** (см. `03-data-structures.md`, `arp_cfg.rate`):
  - unit="note": квант по длительности ноты, `1/64`–`1/1` (например `1/16` =
    четверть BPM при 120 → 125 мс);
  - unit="ms": точный интервал 10–2000 мс, изменение кратно 10 мс;
  - при смене RateMode значение Rate подстраивается: в "note" показывается
    ближайший деленитель, в "ms" — предыдущее число в мс (по умолчанию 100);
- дистанция — диапазон в полутонах (насколько арпеджио "гуляет" за пределы
  базового набора нот, например добавляя ноты на октаву выше);
- количество шагов арпеджио;
- стиль (радиальный селектор, 8 позиций, "вверх" = выкл):
  1. Up (восходящий)
  2. Down (нисходящий)
  3. Up-Down
  4. Down-Up
  5. As played (в порядке нажатия/добавления в аккорд)
  6. Random
  7. Converge/Diverge (сходящийся/расходящийся от центра набора к краям и обратно)

### Настройки арпеджио в PRM (DETAIL, Quick-строка Arp) — на что влияют

Параметры попадают в `arp_cfg` и применяются в двух местах: live-арпеджио
(`ModeEngine._build_arp_seq` + планировщик `tick()`) и паттерн-путь
(`midi_chain.process_note`, генерация полной арп-последовательности событиями).
Порядок внутри арпеджиатора: **Key Filter → Chord → apply_arp_range → style-цикл**.

| Параметр | Что задаёт | Эффект на звук |
|---|---|---|
| **AStyle** (Quick-ячейка / DETAIL) | Манера перебора нот: Off, Up, Down, Up-Down, Down-Up, As Played, Random, Converge/Diverge | Порядок, в котором ноты аккорда/набора играют одну за другой. **Заметен только если в наборе >1 ноты** — для одной ноты все стили звучат одинаково. Достаточное число нот дают: аккорд (Chord ON), несколько зажатых клавиш (поли-арп, latch OFF) или ARange. Стили-«пилы» (Up-Down, Down-Up, Converge/Diverge) требуют **3+ нот**, иначе схлопываются к Up/Down. |
| **Latch** | Удержание арпеджио после отпускания клавиши | ON: одно нажатие включает ноту и держит (арп играет бесконечно), повторное нажатие той же ноты — отпускает; **при latch ON + арп полифония не действует** — новая клавиша заменяет предыдущую (моно-замена). OFF: арп живёт, пока зажата клавиша. |
| **RateMode** | Режим частоты шагов: **Note** (квант по длительности ноты 1/64–1/1) или **Ms** (точные миллисекунды 10–2000, шаг 10 мс) | Выбирает, чем управляет **Rate**. |
| **Rate** | Частота шагов арпеджио | Note: `1/16` = 16-я нота (при 120 BPM ≈ 125 мс), `1/8` ≈ 250 мс, `1/4` = четверть ≈ 500 мс и т.д. Ms: прямое число миллисекунд между нотами. **Меньше значение → быстрее перебор.** |
| **ARange** | `range_semitones` — диапазон в полутонах за пределами базового набора | Добавляет ноты на октавы вверх (в пределах диапазона) к аккорду/одиночной ноте. **При ARange=0 одиночная нота не арпеджируется** — все стили дают одну и ту же повторяющуюся ноту. По умолчанию 12 (одна октава) — 02.08.2026. |
| **ASteps** | `num_steps` — длина цикла арпеджио (1–32) | Сколько нот проигрывает один проход цикла перед повтором. |

**Практические правила (02.08.2026):**
1. Чтобы сменить «манеру игры» на одной зажатой клавише, нужен **ARange > 0**
   (по умолчанию 12) или включённый аккорд. Иначе набор — одна нота, и Up/Down
   звучат одинаково.
2. Up-Down / Down-Up / Converge-Diverge по-настоящему раскрываются на **3+ нотах**
   (аккорд или несколько клавиш).
3. **As Played** в live-режиме играет по отсортированному объединению клавиш
   (эквивалентно Up), т.к. аккорды сливаются в один набор.
4. Стиль применяется в момент пересборки арпеджио (`_restart_arp`) — нажатие/
   отпускание клавиши или смена стиля в меню перезапускает цикл с новой манерой.

## Этап 4 — Timing-эффекты

Применяются к границам ноты во времени, **не трогая pitch**. Порядок внутри блока:

```
swing/groove → humanize → triole/quantize → legato
```

- **Swing/Groove** — смещение чётных (или заданных по маске) шагов от сетки.
- **Humanize** — случайный джиттер тайминга и (в будущем, если появится velocity)
  амплитуды в небольших пределах, для "неидеальности".
- **Triole/квантизация** — принудительное выравнивание длительностей нот по
  выбранной сетке (доступный выбор кратности шагу).
- **Legato** — продление ноты до начала следующей (устраняет паузу/gap между
  нотами), либо принудительное лигато между определённой парой шагов.

## Этап 5 — Gate/ADSR

Так как velocity не используется и звукового движка на устройстве нет — классическая
ADSR-огибающая громкости неприменима напрямую к чистому MIDI Note On/Off. ADSR
трактуется как модель **gate-тайминга**:

- **Attack** — задержка отправки Note On относительно номинального начала шага
  (нота "запаздывает").
- **Release** — задержка отправки Note Off после номинального конца ноты (гейт
  "тянется" дольше номинальной длины).
- **Decay/Sustain** — в отсутствие velocity не имеют физического смысла в чистом
  MIDI-режиме; в UI можно либо скрыть эти параметры, либо оставить как заготовку
  на случай появления CC-выхода (см. `07-roadmap-open-questions.md`).

Приоритет длины ноты: **рандом-параметры (или ручной ввод длины) формируют
номинальную длину — у них приоритет.** ADSR Attack/Release не пересчитывают эту
номинальную длину, а лишь сдвигают фактические моменты отправки Note On/Off
относительно неё — то есть ADSR это эффект, применяемый **поверх** уже готовой
длины, в самом конце конвейера (после timing-эффектов, которые тоже могли изменить
номинальные границы шага через quantize/legato).

## Live-режим (живая игра с клавиш)

Когда `process_note()` вызывается с `live=True` (режимы midi_keyboard, midi_filter,
random_note), тайминг-эффекты (swing, humanize, quantize, legato) и ADSR
пропускаются — ноты отправляются мгновенно, без задержек. Key Filter, Chord Builder
и Arpeggiator работают в полную силу.

## Итоговый порядок применения (сводка)

1. Key Filter
2. Chord Builder (со вторичной фильтрацией структуры, если Key Filter включён)
3. Arpeggiator
4. Swing/Groove → Humanize → Triole/Quantize → Legato *(пропускается в live-режиме)*
5. Gate/ADSR (Attack/Release delay) *(пропускается в live-режиме)*
6. MIDI Note On/Off → OUT

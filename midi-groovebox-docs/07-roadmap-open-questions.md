## Закрытый вопрос: распиновка Rest (закрыт 01.08.2026, УТОЧНЁН 02.08.2026)

Изначально по логу `FUNC` приняли Play=bit0, Rec=bit1, OctDown=bit2, OctUp=bit3,
Rest=bit6, Shift=bit7. **Тестовая прошивка (подсветка кнопок «+»/«−») и лог `FUNC`
со сверкой с физическими нажатиями (02.08.2026) зафиксировали точную распиновку:**

| Бит | Кнопка |
|---|---|
| bit0 | Play |
| bit1 | Rest |
| bit2 | Rec |
| bit3 | Shift |
| bit6 | OctUp («+») |
| bit7 | OctDown («−») |

Причина «неработающей октавы» до 02.08.2026: физические Oct+/Oct− давали фронты
на bit7/bit6, которые код трактовал как Shift/Rest. Код (`code.py`), дока
`01-hardware.md` и `05-input-mapping.md` приведены в соответствие.

## Закрытый вопрос: транспорт Play/Rec для Ableton (закрыт 02.08.2026)

Play/Rec ранее только переключали локальный секвенсор и не отправляли MIDI, из-за
чего Ableton не видел транспорт. Добавлено: Play шлёт **Start** (0xFA) / **Stop**
(0xFC) в зависимости от перехода состояния, Rec шлёт **Continue** (0xFB) по фронту
нажатия (решение принято с заказчиком — вариант Start/Stop realtime). Реализовано в
`midi.py` (методы `transport_start/stop/continue`) и `code.py`.

## Закрытый вопрос: арпеджиатор в live-режиме + одиночная нота (закрыт 02.08.2026)

Арпеджиатор не работал в live-режиме: `process_note` генерировал все арп-ноты с
тиковыми смещениями, но `ModeEngine.note_on` слал их все сразу — планировщика по
времени не было. Исправлено: в `ModeEngine` добавлен планировщик live-арпеджио
(`_arp_state` / `_start_live_arp` / `_advance_arp` / `tick()`), играет по
`time.monotonic()` с интервалом из `arp_cfg.rate` и текущего BPM; `tick()` вызывается
в главном цикле `code.py`.

Дополнительно арп разблокирован для **одиночной ноты** (раньше требовал
`chord_cfg.enabled` И `len(notes) > 1`): теперь одиночная нота арпеджируется по
`range_semitones` (октавы вверх/вниз в зависимости от стиля).

## Закрытый вопрос: Latch (закрыт 02.08.2026)

Реализован как **глобальный тумблер** в меню (`arp_cfg.latch`, пункты "Latch" в
Quick-меню Arp и MAIN → Arpeggiator) — без Shift-комбинаций, чтобы не конфликтовать
с числовым вводом. Поведение: одно нажатие ноты включает её и держит (арп играет
бесконечно даже после отпускания), повторное нажатие той же ноты — отпускает.
`all_notes_off()` сбрасывает и арп, и latch. Работает и без арпеджиатора (просто
залипание ноты).

**Уточнение 02.08.2026:** при latch ON + арпеджио нажатие новой (другой) клавиши
**заменяет** предыдущую защёлкнутую ноту (моно-замена) — см. раздел про
полифонический арпеджио ниже.

## Закрытый вопрос: полифонический арпеджио + Key Scale + Chord (закрыт 02.08.2026)

Первоначально (02.08.2026) с заказчиком был зафиксирован **моно-арпеджио**: нажатие
новой ноты снимало предыдущие. Затем заказчик запросил полифонию и совмещение с
Key Filter + Chord — моно отменено, реализовано:

- `midi_chain.build_note_set(raw_note, pattern)` — единый конвейер
  Key Filter → Chord Builder → secondary_filter (используется и `process_note`,
  и live-арпеджио).
- `ModeEngine` держит **один общий арп** (`_arp_playing`) по объединённому аккорду
  всех зажатых клавиш (`_arp_notes: chip_idx -> raw_note`). Нажатие/отпускание
  клавиши пересобирает аккорд и перезапускает цикл арпеджио.
- Несколько одновременных клавиш (без арпа) тоже играют полифонично
  (`_held_notes[chip_idx]` на каждую клавишу).

Арp-планировщик live: `_restart_arp` / `_advance_arp` / `tick()` по
`time.monotonic()` с интервалом из `arp_cfg.rate` и текущего BPM; `tick()`
вызывается в главном цикле `code.py`. Одиночная нота арпеджируется по
`range_semitones` (октавы вверх/вниз в зависимости от стиля).

**Уточнение 02.08.2026 (latch):** полифония по зажатым клавишам действует при
**latch OFF**. При **latch ON** + арпеджио — **моно-замена**: нажатие новой
клавиши снимает ранее защёлкнутую (`_latched`/`_arp_notes`) и арпеджирует на
новой; повторное нажатие той же защёлкнутой клавиши — отпускает (как раньше).

**Автопроверка конфигурации:** `ModeEngine.tick()` вызывает `_check_config()`:
если арпеджиатор выключен в меню/режим не арпеджио — `_stop_arp()` + очистка
`_arp_notes`; если latch выключен — защёлки снимаются (арп-ноты гасятся,
залипшие обычные ноты — через `_release_chip`), при пустом наборе арп гасится.

## Закрытый вопрос: единый параметр Rate + RateMode (закрыт 02.08.2026)

RateDiv и RateMs объединены в один параметр **Rate**; добавлен переключатель
**RateMode** ("Note" — квант по длительности ноты 1/64–1/1; "Ms" — точный
интервал 10–2000 мс, изменение кратно 10 мс). В menu.py новый тип элемента
`"rate"` (`rate_item`): в режиме note работает как option-цикл по делениям,
в режиме ms — как int_slider с шагом 10 (Shift+влево/вправо — крайние значения).
Структура `arp_cfg.rate = {"unit": "note"|"ms", "value": ...}` не изменилась,
логика `_arp_interval_ms()` не затронута. Применено в Quick (Arp → PRM) и
Full (Arpeggiator → RateMode/Rate).

## Закрытый вопрос: «стиль арпеджио не меняется» + дефолт ARange (закрыт 02.08.2026)

Жалоба: выбор Up/Down/... в AStyle не менял манеру игры. Диагностика: код стилей
корректен (`arpeggiator.generate_arp_cycle` даёт разные последовательности при
нескольких нотах); причина была в настройках — при **ARange=0** и одиночной ноте
(Chord OFF, одна клавиша) набор состоит из одной ноты, и все стили дают одну и ту же
повторяющуюся ноту.

Исправление: `arp_cfg.range_semitones` по умолчанию **12** (был 0) — `state.py`,
плюс фолбэки `ac.get("range_semitones", 12)` в `mode_engine._build_arp_seq` и
`midi_chain.process_note`. Теперь даже одна зажатая клавиша арпеджирует по октаве,
и Up/Down слышно разными. Стили-«пилы» (Up-Down, Down-Up, Converge/Diverge)
по-прежнему требуют 3+ нот. Описание настроек PRM добавлено в `02-midi-chain.md`.

- В Quick-строку **Arp** добавлена линейная ячейка **Latch** (Off/On) между

- Частота арпеджио по умолчанию — **1/8** (была 1/16): `state.arp_cfg.rate`,

## Закрытый вопрос: индикация и применение октавы (закрыт 02.08.2026)

Октава нотных клавиш хранится в `runtime.base_octave` (по умолчанию 4), отображается в
статус-баре как `o{октава}`. Раньше смена октавы работала в логах, но пользователь её
"не видел" — индикатора не было, а `pattern.transpose` не применялся в конвейере.
Исправлено:

- `midi_chain.process_note` применяет `pattern.transpose` (полутоны + октавы) к сырой
  ноте **до** Key Filter (см. `02-midi-chain.md`), влияя и на живой ввод, и на
  записанные ноты;
- кнопки **OctUp/OctDn — чисто программное управление устройством** (не MIDI-сигналы):
  меняют `runtime.base_octave`, который `code.py` применяет к нотам нотных клавиш
  (`note = base_octave*12 + (i % 12)`), читая значение из state на каждое событие;
- добавлен пункт MAIN → Octave → Base Octave (1–8) — программная смена октавы через
  меню, дублирует кнопки и не зависит от распайки кнопок.

## Отложено на будущее (сознательно, зафиксировано с заказчиком)

- **UART MIDI DIN** (OUT сейчас в плане, IN — после OUT). Требует выбора GP-пинов
  под UART и, для IN, оптрона (6N138/PC900) — см. `01-hardware.md`.
- **MIDI Clock sync** — синхронизация BPM с внешним оборудованием (сейчас только
  внутренний генератор темпа).
- **Сохранение паттернов на flash/ПЗУ** — сейчас 16 слотов только в ОЗУ, теряются
  при выключении питания. Структуры данных (`03-data-structures.md`) спроектированы
  сериализуемыми заранее, чтобы переход на ПЗУ не потребовал переработки схемы.
- **Velocity-чувствительный ввод** — сейчас кнопки дают только on/off. Поле
  `velocity_mode` в `random_cfg` уже заложено в структуру данных на будущее.
- **Энкодер** — сейчас весь точный ввод значений идёт через джойстик (короткий тап,
  Shift+тап для крайних значений, удержание для авто-повтора). Энкодер может быть
  добавлен позже без изменения логики верхнего уровня (просто ещё один источник
  событий "increment/decrement/jump-to-extreme").
- **CC-выход / полноценная ADSR-огибающая** — если в будущем добавится звуковой
  синтез на самом устройстве или расширенный контроль внешнего синта через CC,
  ADSR может перестать быть только "gate-моделью" (см. `02-midi-chain.md`) и
  получить отдельный параллельный CC-поток.

## Закрытый вопрос: авто-повтор джойстика (закрыт 02.08.2026)

Удержание джойстика в любом из 4 направлений повторяет действие с ускорением:
навигация по пунктам/строкам (UP/DOWN) и быстрый ввод значений (LEFT/RIGHT).
`REPEAT_START_MS=350`, затем ступени 150/80/40/25 мс. В радиальном селекторе
авто-повтор не действует. Таймер сбрасывается при отпускании/смене направления.

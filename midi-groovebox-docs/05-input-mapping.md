# Распределение функций по вводу

## Физические кнопки

- **16 нотных кнопок** — ввод нот. Раскладка: кнопки 1–12 = C..B текущей октавы
  (`runtime.base_octave`), кнопки 13–16 = C, C#, D, D# **на одну октаву выше**
  (`base_octave + 1`) — продолжение клавиатуры.
- **6 функциональных кнопок**: Play, Rest, Record, Shift, Octave Down, Octave Up.
  (см. `01-hardware.md`, битовая карта chip3).

Чтение: каскад 74HC165, 24 бита, активный уровень LOW; двойной опрос +
пер-кнопочный дебаунс (фильтр дребезга, System → Debounce).

## Джойстик KY-023

Аналоговый X/Y + кнопка (GP15, активный LOW). Используется для:

1. Навигации по меню (тап влево/вправо = ±1, удержание — авто-повтор).
2. Радиального выбора лада/аккорда/стиля арпеджио/струма (8 секторов).
3. Ввода значений параметров (±1 шаг; Shift + наклон — крайние значения).
4. Клик — вход/подтверждение/edit-mode; long-press — pop / смена экрана.

Авто-повтор с ускорением: при удержании джойстика в одном направлении интервал
повтора падает (190 → 140 → 100 → 70 → ~45 мс), а на самом быстром уровне за тик
выполняется до 4 наклонов (`app_loop.cpp`, `joy_hold_ms_`). В радиальном селекторе
авто-повтор не действует (выбор зоны разовым наклоном).

## Отличие поведения (зачастую)

Хендлинг ввода сосредоточен в `AppLoop::process_notes()` /
`process_functional()` / `process_joystick()`:

### Нотные клавиши

- Подтверждаются только после удержания нового уровня N чтений подряд
  (`kKeyDebounce = 5` кадров ~5–10 мс). Чистый отпуск распознаётся корректно
  (сбрасывается только при стабильном состоянии), поэтому ноты не «залипают».
- Нажатие → `mode_.note_on(chip_idx, button_to_note(i), now_ms)`; отпускание →
  `mode_.note_off(chip_idx, now_ms)`. В test mode MIDI не слается.

### Функциональные кнопки (chip3)

Каждая кнопка дебаунсится независимо по времени (`func_pending_start_`):
состояние переключается только после удержания на `debounce_ms` (3–60 мс,
по умолчанию 12 мс). Дребезг, вернувший старое значение, сбрасывает таймер —
один клик даёт ровно один фронт.

| Кнопка | Функция | MIDI CC (вне test-mode) |
|---|---|---|
| **Play** | переключение `playing` (в RND — старт/стоп цикла случайной ноты) | CC20 (127/0) |
| **Rest** | live-mute пока зажата; Rest+клик джойстика — сброс значения | CC21 |
| **Record** | переключение `recording` (в alpha no записи паттерна) | CC22 |
| **Shift** | модификатор (крайние значения, тест-выход и т.п.) | CC23 |
| **OctDown/OctUp** | −/+ базовой октавы клавиатуры (0..8 + сдвиг 2) | CC25 / CC24 |

CC-дубли отправляются на **MIDI-канале 16** (`kCcChan = 15`, 0-based), нажатие=127,
отпускание=0. В test mode НЕ отправляются (чтобы тестер видел только чистые
сигналы входа).

## Радиальный селектор джойстика

Все радиальные параметры QUICK (Scale, CType, AStyle, Strum) используют единый
механизм: 8 секторов по направлению вектора `poll()` джойстика →
`direction_to_zone()`:

| Зона | Направление | Scale | CType | AStyle | Strum (мс) |
|---|---|---|---|---|---|
| 0 | Вверх | Off | Off | Off | Off |
| 1 | Верх-право | Major | Maj | Up | 10 |
| 2 | Вправо | Minor | Min | Down | 20 |
| 3 | Вниз-право | Dorian | Maj7 | Up-Dn | 30 |
| 4 | Вниз | Phrygian | Min7 | Dn-Up | 40 |
| 5 | Вниз-влево | Lydian | Dom7 | Play (As Played) | 50 |
| 6 | Влево | Mixolydian | Sus4 | Rnd | 75 |
| 7 | Вверх-влево | Blues | Pow | CvDv | 100 |

### Поведение радиальных ячеек QUICK

- Требуют **клика** джойстика для входа в edit-mode; движение в любом направлении
  выбирает зону; повторный клик выходит.
- **Без клика** наклон влево/вправо на радиальной ячейке только перемещает фокус.
- Линейные ячейки (Key, Dens, Shape, REP) — тоже клик-цикл: клик → влево/вправо меняет
  значение → клик.
- В DETAIL/MAIN радиального управления нет: все пункты редактируются влево/вправо
  сразу, без клика.

### Note Range и Len Range (2D, QUICK `Rand` / DETAIL)

`Randomize → NT_RNG` / QUICK-строка `Rand` — двумерные «от–до» контролы с общей
механикой: клик активирует редактирование, **вверх/вниз** меняет только
**верхнюю (макс.) границу** на 1 шаг, **влево/вправо** сдвигает центр диапазона
(обе границы на 1, ширина сохраняется). Повторный клик подтверждает; Rest+клик /
двойной клик — сброс к последнему принятому значению. Пока диапазон редактируется,
курсор не двигается — джойстик целиком занят контролом.

- **PITCH** (в коде NT_RNG) — диапазон высоты: случайная нота выбирается в
  интервале `[note_min … note_max]` (MIDI). Текст без разделителя (`F#2D#4`),
  чтобы ячейка не наезжала на соседнюю при диезах.
Range-механика ячеек: **вверх** расширяет диапазон (max+1), **вниз** сужает (max−1, до закреплённой точки), **влево/вправо** сдвигают центр; при min==max влево/вправо перетаскивают закреплённое значение.
- **PITCH** (в коде NT_RNG) — диапазон высоты: случайная нота выбирается в
  интервале `[note_min … note_max]` (MIDI). Инверсия ячейки растягивается под
  текст (`F#2-D#4`). Тот же контрол есть в FULL → Randomize → **Note Range**.
- **LEN** (в коде LEN_RNG) — диапазон длины ноты по таблице `kNoteLenDivs[16]`
  в компактных метках без «1/»: `128 96 64 48 32 24 16 12 8 6 4 3 2` (= 1/N)
  и `'1 '2 '4` (целая, две, четыре целых). На каждом шаге RND длительность
  гейта тянется равномерно из диапазона. **min == max фиксирует длину** — в
  ячейке одно значение (`4` = четверть). Release (Gate ADSR) сдвигает
  фактический Off позже границы.
- **Len Chain** (FULL → Randomize) — тайминг RND:
  - *Off*: шаги по сетке ARP Rate, длина капится интервалом шага;
  - *On*: свободная цепочка — следующая нота стартует ровно в момент окончания
    гейта предыдущей (после ноты `64` сразу звучит следующая), ARP Rate на
    расстановку нот не влияет; каждый шаг артикулируется, пол шага 20 мс.
- Полоса диапазона под строкой видна **только во время редактирования**
  конкретной Range-ячейки; вне редактирования полосы не рисуются (в строке две
  Range-ячейки, постоянные полосы накладывались бы друг на друга).

Ячейка **REP** в той же строке — шанс повтора якорной ноты (последняя нажатая
клавиша KEY или корень тональности при старте по Play): 0–90 %, шаг 10 %. Если
якорь лежит вне PITCH, берётся только его **имя ноты**, октава подстраивается к
ближайшему вхождению в диапазон (C0 при диапазоне C1-C2 → C1); если диапазон
уже октавы и класса якоря в нём нет — якорь подрезается границами. REP даёт
явный ретригер якоря в обоих режимах Len Chain, чтобы повтор был слышен.

### Заголовок QUICK — переключатель режима KB/RND/PTRN

Заголовок (статус-бар) на QUICK показывает текущий режим, а сам является
отдельной зоной навигации. С **любой** ячейки первой строки наклон **вверх**
уводит фокус на заголовок (режим инвертируется), **клик** циклит `KB→RND→PTRN→KB`,
наклон **вниз** возвращает на строку в ту же колонку, откуда ушли; влево/вправо
из заголовка — то же, но со сдвигом колонки. Режим меняется сразу, QUICK
перестраивается под новый набор строк (AppLoop глушит ноты и пересобирает меню
при смене `runtime.mode`). Это единственное место ручного переключения режима
устройства.

### PTRN — генерация и воспроизведение паттерна

- **клавиша** — генерирует случайный паттерн от этой ноты и сразу запускает цикл;
  повторное нажатие **той же** клавиши — стоп; другая клавиша — новая генерация;
- **Play** — старт/стоп цикла без перегенерации;
- событие = моно-нота из PITCH (фильтр в лад) или rest (шанс = Dens); длительность
  события берётся из LEN, следующая нота стартует ровно на окончании гейта
  предыдущей (как Len Chain в RND); REP повторяет предыдущий тон с указанным
  шансом; длина последовательности — `pattern.length` (16 событий);
- параметры — QUICK-строка `Rand` (PITCH/LEN/REP) и `ALL` (Dens, STEP — длина
  паттерна 4/8/16/32/64; клик по имени ALL открывает FULL-меню). Gate %
  (Randomize DETAIL) задаёт гейт в % длины события; Regen перегенерирует паттерн.

### Pattern Editor (EDIT) — запись и редактирование

Вход: long-press цикл Quick → FULL → **EDIT** (или после записи в режиме
Pattern). Сетка шагов — 1/16 такта (переключатель `Pattern.grid64` → 1/64,
Randomize → Grid64), длина цикла — поле **PLEN** в редакторе или ячейка STEP
(4/8/16/32/64 шага).

**Экран**: пиано-ролл на всю ширину — 16 шагов страницы по 8 px; нота = блок
3×3 на строке своей высоты + хвостик длительности; rest не рисуется; строки
высоты **авто-масштабируются** под ноты паттерна (скрыты неиспользуемые ряды,
окно растёт при добавлении новых нот); **единый маркер текущего шага** =
тик над роллом + вертикальная полоса (playhead) в одной колонке — это же место
редактирования: Play движется по колонкам, стоп замирает на редактируемом шаге;
индикатор `1/N` — номер страницы (при длине >16).

**Запись (Rec)**: включает тихую сетку-транспорт и **пишет в слот всё, что
воспроизводится** в любой режим, а не только PTRN: мелодия миди-клавиатуры
(питч = нажатая клавиша), поток случайных нот (RND) — всё квантуется к
ближайшему шагу и фиксируется в активном паттерне. Длительность нажатия →
ближайшее деление LEN. Rec **не стирает** записанное: пока запись включена,
**живая перезапись** — пустой шаг получает ноту, на шаге с нотами старая
заменяется на новую, а шаги, до которых пользователь не дотронулся, остаются
как были. Повторный Rec — стоп записи.

**Редактирование** — нота присваивается **текущему (отмеченному) шагу** —
месту, где остановилось воспроизведение:
| Ввод | Действие |
|---|---|
| ← / → | двигать **текущий шаг** (маркер/playhead) внутри страницы |
| Shift+← / → | текущий шаг −16 / +16 (страница ±1) |
| **нотная клавиша** | присвоить ноту **текущему** шагу (маркер остаётся там → сразу виден `±`) |
| ↑ / ↓ | правка сфокусированного значения **текущего шага** |
| **Rest в NOTE-фокусе** | **вернуть исходную ноту** (Undo) — восстанавливает prev, если нота была изменена, а не стереть |
| **Rest+клик** | стереть ноту текущего шага |
| **Shift+Rest** | стереть все ноты видимой страницы |
| Play | в EDIT — **всегда** старт/стоп прослушивания **слота паттерна** (Play из RandomPattern после входа в EDIT тоже озвучивает паттерн, а не генератор); маркер движется по шагам, стоп — на редактируемом шаге |

**Наглядность правки питча** (поле NOTE + ↑/↓ или октава):
- Исходная нота запоминается **по-шагово** (`prev_notes[]`, первое касание
  шага): каждый шаг хранит свою оригинальную ноту, поэтому `±` и Undo работают
  для любого шага, независимо от навигации после правки.
- Рядом с нотой — **знак направления**: `+` справа, если новая нота стала
  выше; `−` слева, если ниже — сразу видно, куда сдвинули и куда вернуться.
  Название ноты при этом **не сдвигается** — слева и справа от него
  зарезервированы слоты под значки (учитывая возможный `#` в имени).
- **Rest** в NOTE-фокусе возвращает исходную ноту (prev), в том числе если
  шаг изначально был пустым (→ обратно в rest). Исходные сбрасываются при
  стирании шага/страницы, генерации нового паттерна или укорачивании PLEN.

**Горячие клавиши (Shift + нотная кнопка)** в EDIT — работают со **всей
видимой страницей (16 шагов)**, а не одиночной нотой:
| Shift+нота | Действие |
|---|---|
| **C (key0)** | **Копировать** страницу в буфер (32 шага под 2 страницы) |
| **C# (key1)** | **Вставить** буфер поверх видимой страницы |
| **E (key4)** | **Дублировать**: копировать текущую страницу и дописать её на страницу **позади**, при необходимости удлиняя петлю паттерна (до 64) |
| **D (key2)** | **Undo** — откат последнего изменения (шага или страницы/дубля) |
| **D# (key3)** | **Redo** — повтор отменённого изменения |

- Shift+ногная клавиша **не пишет ноту** — только команда.
- Полный **undo/redo**: любые правки шага (нота/длительность/включение октавы/
  PLEN) и целые операции страницы (копировать/вставить/дубль) кладутся в
  очередь как `{index, old/new step, old/new prev, длина до/после}`.
  Логика: перед правкой фиксируется граница батча; до 32 записей (батчи
  режутся по операциям, при переполнении отбрасывается **самая старая
  операция** целиком); каждая новая правка очищает redo-путь.
- Undo/Redo восстанавливают также per-step «исходную ноту» (`prev_notes`) и
  длину петли, так что `±`-индикатор и шаговый Rest-undo не «рассинхрониваются».
- При срабатывании команды в верхнем желобе на ~0.7 с показывается индикатор:
  `COPY`, `PAST`, `DUPL`, `UNDO`, `REDO`.

> **Авто-переход страниц**: `cur` — абсолютный индекс шага, страница всегда
> `cur/16`. Наклоном вправо/влево индекс растёт/падает по шагам и замыкается
> по циклу: 16→17, 17→16, 32→1, 1→32. При длине ровно 16 — вправо с 16-го и
> влево с 1-го замыкаются (16→1, 1→16). Shift+наклон — переход на страницу ±1
> (сохраняя колонку курсора).
>
> В режиме EDIT **все генерации заблокированы**: нотные клавиши не запускают
> RandomNote/RandomPattern и не перегенерируют слот — даже если пользователь
> пришёл в редактирование прямо из режима случайного паттерна.
>
> Простое движение курсора (←/→) **не** перезаписывает ноты и **не**
> запускает перегенерацию — только клик по шагу делает его приёмником
> ввода, поэтому случайная навигация не портит паттерн. Во время
> воспроизведения по роллу движется **тонкая вертикальная полоса-маркер**
> текущего шага; курсор — верхняя плашка над колонкой, выбранный шаг —
> скобка под нижней линией.
>
> Знак `+`/`−` у ноты — статус незавершённого изменения питча: показывается
> всегда, пока правка не подтверждена (клик) и не отменена (Rest).

↑/↓ по полям: NOTE — хроматика ±1 (**Shift — октава ±12**); LEN — деления
`'128 … '2 … '1`; ON — вкл/выкл; PLEN — длина паттерна 4/8/16/32/64
(укорачивание стирает шаги за новой границей).

### Анимация — запуск

Ручной запуск анимации и таймер простоя живут в System → **Anim / Idle Anim** (long-press цикл
переключает только Quick ↔ Full). После запуска любой ввод возвращает на экран,
откуда анимация была вызвана; автозапуск по простою (Idle Anim) работает так же.

## Сброс значения

- **Rest + клик джойстика** (в любом меню): сброс к снимку на момент фокусировки
  (QUICK — ячейки на входе в edit-mode). Срабатывает, если Rest зажата в момент
  клика (`fn_pressed(kBtnRest)`).
- **Двойной клик** (~`double_ms`, 300 мс) — дополнительный сброс в DETAIL/MAIN.
- Отрицательное подтверждение: если Rest не был зарегистрирован фронтово — клик
  идёт в `press_short()` (вход в edit / entry через PRM).

## Кнопка Shift

Модификатор: Shift + наклон = крайние значения; Shift + клик в test-mode =
выход из теста; Shift + Rest (обнуление паттерна) — в alpha не реализовано
(в roadmap).

## Экран Test

Запускается из Full-меню System → **Test**. На нём:

- показываются живые образы входа (`note_bits` — 16 нотных клавиш, `func_bits` =
  подтверждённый образ chip3);
- кнопки **не действуют** (не переключают транспорт/октаву/CC) — только
  отображаются;
- выход — **Shift + клик джойстика** (возврат в Full-меню, ноты резко глушатся).

Экран полезен для сверки распиновки функц. кнопок на плате (см. `01-hardware.md`).

## Октавы и транспонирование

- **OctDown/OctUp** — базовая октава клавиатуры (`base_octave`, 0..8, отобр. в
  статус-баре). Не влияет на transpose-структуру, только на последующий ввод.
- Отдельное транспонирование (`transpose.semitones/octaves`) применяется в
  конвейере к сырой ноте ДО Key Filter (см. `02-midi-chain.md`).
- В Full-меню: Transpose → Semitones/Octaves/Base Octave.
